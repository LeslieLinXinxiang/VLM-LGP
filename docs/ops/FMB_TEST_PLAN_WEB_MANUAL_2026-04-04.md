# FMB 测试方案提案 A：网页端手工输入最小化测试

- 日期：2026-04-04
- 目标：不接入主线代码，仅通过网页端按序图片输入验证协议可行性与输出格式稳定性。
- 输入主模态：固定视角 sequential 灰度装配图（单一模态）。

## 1. 测试目标

1. 验证模型能否在固定顺序多帧输入下稳定输出 Phase0 风格 JSON。
2. 验证 few-shot 在低样本条件下是否改善遮挡场景。
3. 验证灰度渲染是否足以完成对象绑定（尽量去除颜色依赖）。

## 2. 测试输入准备

必须准备：

1. Prompt 文本：`prompts/phase0_fmb_sequential_binding.md`
2. 真实任务图片文件夹：按顺序命名的图片，例如 `001.png`、`002.png`、`003.png`
3. Few-shot 固定目录：每组包含 `step_*.png` + `expected_output.json`
4. Few-shot 索引：`test/fmb_protocol/fewshot/fewshot_manifest.json`（仅用于人工/脚本索引，不作为真实任务输入）

## 3. 网页端交互顺序（严格）

在网页交互中按以下顺序粘贴/上传，不允许打乱：

1. 粘贴 prompt 主文本（来自 `phase0_fmb_sequential_binding.md`）。
2. 逐组注入 few-shot：
   1. 粘贴该组 folder 名称或简短 focus 名称。
   2. 上传该组顺序帧（按 `step_01` -> `step_N`）。
   3. 粘贴该组 `expected_output.json`。
3. 注入真实任务：
   1. 选择真实任务图片文件夹。
   2. 按文件名顺序上传/粘贴真实任务图片。
   3. 追加 `Return JSON only.` 约束。

## 4. 输出与验收

### 4.1 预期输出

模型返回 JSON 数组，元素键包含：

1. `anon_id`
2. `logical_id`
3. `shape`
4. `object_type`
5. `size_signature`
6. `color_rgb`

### 4.2 验收项

1. JSON 可解析。
2. 输出结构与 Phase0 风格一致。
3. 多次重复提问输出稳定（命名不漂移）。
4. 遮挡场景下输出完整率可接受。
5. 不出现“按颜色直接猜身份”的文本痕迹。

## 5. 最小实验矩阵

建议先跑三组（每组至少重复 3 次）：

1. 无 few-shot + 灰度序列
2. 2-shot + 灰度序列
3. 3-shot + 灰度序列

记录指标：

1. JSON 成功率
2. 对象绑定正确率
3. 输出稳定性（同输入多次一致率）

## 6. 失败处置规则

1. 若 JSON 结构错误：先压缩 prompt 文本冗余，再强化 `JSON only` 约束。
2. 若对象漂移：减少 few-shot 数量并检查示例是否概念重叠。
3. 若灰度表现明显不足：保留同一流程，仅切换彩色图二次对照，不改顺序结构。

## 7. 产出物

1. 测试记录表（每轮输入配置、输出、判定）。
2. 失败案例集合（原输入 + 原输出 + 错误标签）。
3. 最终推荐 few-shot 组数（2 或 3）。
